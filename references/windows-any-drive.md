# 非系统盘（D:/E: 等）数据布局与分级参考

分析非系统盘扫描结果时读这份。讲「东西存在哪、怎么辨认、归哪一级」。
C 盘布局见 [windows-c-drive.md](windows-c-drive.md)。

## 与 C 盘的根本差异

| 维度 | C 盘（系统盘） | 非系统盘（D盘等） |
|---|---|---|
| 主导占用 | 系统文件 +应用缓存 | **用户数据**：工作资料、聊天记录、媒体文件 |
| 缓存占比 | 高（Temp、浏览器、开发缓存） | 低，缓存类内容少 |
| 可逆性 | 缓存删了自动重建，风险低 | **多数是不可再生的工作数据** |
| 清理建议 | 可给 🟢 直接删 | **最高只给 🟡 移到回收站** |
| 最大价值 | 清缓存释放空间 | 找重复文件、清陈旧数据 |

⚠️ **非系统盘不得给「直接删除」按钮**。`server.py` 在 `non_system_drive: true` 时自动清空 rm 白名单。

## 常见可清理模式（非系统盘）

### 1. 压缩包与其解压目录并存
网盘下载目录里常见 `软件安装包.rar` 与 `软件安装包\\` 同时存在。已确认解压并归档后，
压缩包可清。这是网盘目录最大的水分来源。

### 2. 同一份文件的三处副本
工作场景里同一份验收材料常同时存在于：微信接收目录、网盘下载目录、项目交付目录。
处置原则：**保留项目交付目录里的那份**（命名规范、便于归档），清掉微信/网盘里的副本。

### 3. 新旧客户端的数据双份
装了新版客户端后，旧目录往往不会自动清理。**但必须取证才能下结论**：
- 比对两侧文件的头部指纹，确认内容一致
- **检查旧目录是否仍在被写入**（若 `Msg` 等子目录的最后写入时间是今天，说明它仍是活动副本，不可删）

判定为「仍在使用」时，正确做法是在客户端内清理，而不是删目录。

### 4. 设备整机备份
微信/QQ 的「手机备份」会导出完整手机数据。若新旧客户端各存一份，重复占用极大
（本机实测 22.4 GB）。这是**用户数据的备份**，删除前必须让用户确认，且优先走客户端内操作。

### 5. 索引与缓存
- Everything 索引（`D:\\Index`）：在 Everything 选项中排除大目录后重建，比直接删更有效
- 崩溃转储（`.dmp`）：纯垃圾，可安全删除
- 未完成下载残片（`.partial/.part/.crdownload`）：纯垃圾

## 绝不可手删（非系统盘同样适用）

| 路径 | 原因 |
|---|---|
| `D:\\Docker\\*.vhdx` | Docker 虚拟磁盘，手删导致全部容器数据丢失、应用无法启动 |
| `D:\\Index\\*` | Everything 索引，手删需数小时重建 |
| `D:\\Program Files*\\` 下的应用 | 手动删文件破坏安装状态，走正规卸载 |
| `D:\\WSL\\*.vhdx` | WSL 发行版磁盘 |
| 任何受保护目录 | 技能层面硬拒绝 |

## 判定「久未使用」

Windows 默认开启 atime 更新（`DisableLastAccess = 0`），因此**最后访问时间可用**：
```
fsutil behavior query disablelastaccess→ DisableLastAccess = 0
```
但注意：atime 的更新由系统延迟维护，目录整体 atime 可能失真；
`stale_files` 已同时给出 `mtime`（最后修改）与 `atime`（最后访问），以mtime 交叉验证。

## 重复检测的判据与局限

本技能的重复检测 = **体积 + 文件头部 1MB 的 sha256**，属**近似算法**：

- ✅ 可靠捕获：同一文件的多份拷贝、改名副本、跨目录归档副本
- ⚠️ 可能误判：同体积且头部 1MB 相同但后续内容不同的文件（罕见但存在）
- ❌ 捕获不到：体积不同的部分修改版本、头部不同的压缩包

**报告中必须原样呈现「近似，非精确」的说明，不得断言「已确认重复」。**

## 长期建议（写进报告 long_term）

1. Everything 排除大目录索引（工作目录、微信目录），通常能省下 10 GB 以上
2. 工作资料按年份打包归档到外部存储或云盘，不要无限堆积在本地
3. 微信/QQ 客户端内定期清理聊天记录与文件缓存
4. 定期运行非系统盘扫描（单次约 45 秒/ 365 万文件），把「清理」变成常规动作
